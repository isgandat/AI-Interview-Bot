## 1) Executive Summary

This project delivers an **AI-powered interview practice tool** with both a **Terminal (CLI)** and a **Web UI**. The system asks **domain‑specific questions** (Software Engineering / Data Science / Behavioral), **evaluates** the candidate’s answer with **structured JSON feedback** (scores + summary + tips + ideal answer), and **logs sessions** for progress tracking.  

The latest version removes the need for a handcrafted question bank: **all questions are generated on-the-fly** by a local LLM via **Ollama**, with **diversity logic** (topic & difficulty rotation) and **de‑duplication** across sessions. The Web UI is implemented with **FastAPI + Jinja + HTMX + Tailwind**, and includes a **“New question”** button to skip a prompt without answering. The project is packaged with **Poetry**, tested with **pytest**, and wired for a minimal **GitLab CI** pipeline.

## 2) Objectives & Success Criteria

### Objectives
1. **Interview Loop** (CLI + Web): present one question, collect an answer, return structured feedback.
2. **LLM-only Question Generation**: domain-aware, diverse, and non-repeating without seed files.
3. **Robust Evaluation**: numeric rubric (clarity, correctness, structure, depth, communication) + summary, tips, ideal answer; resilient JSON parsing.
4. **Persistence**: per-session logs and a global “asked index” to prevent repeat questions across runs.
5. **Usable Web UI**: simple, modern interface with “Submit answer”, **“New question”**, and “New session” actions.
6. **Reproducibility**: local, open-source model through **Ollama**; Poetry-managed environment.
7. **Automation**: GitLab CI that installs with Poetry and runs smoke tests.

### Measurable Success
- ✅ CLI and Web loops run locally and **save logs** (JSON) under `storage/`.
- ✅ Questions are **generated on-the-fly** and **rarely repeat** (global asked index + near‑duplicate check).
- ✅ **Feedback** arrives in structured JSON even when the model is messy (auto-repair fallback).
- ✅ **Web UI** operates with domain selection, neat styling, history, and **“New question”** button.
- ✅ CI pipeline green on default branch (stub included; expand tests as features grow).

## 3) Scope

### In Scope (current MVP)
- Domains: **software_engineering**, **data_science**, **behavioral**.
- **LLM generation only** (no static seed YAML).
- Diversity mechanisms: topic/difficulty tracking and **near‑duplicate detection** (Jaccard).
- JSON session logging and a global `asked_index.json` to prevent repeats across sessions.
- CLI and Web UI; local persistence to disk.
- Simple CI (`.gitlab-ci.yml`) + `pytest` smoke test.

### Out of Scope (for now)
- Multi-user accounts, auth, or DB-backed storage.
- Live token streaming.
- Cloud providers (OpenAI, etc.) — optional future switch.
- Advanced analytics dashboards and cohort reports.
- Cluster (MetaCentrum) runs — **planned as future work**.

## 4) System Overview

### User Flow (Web)
1. Open the app, pick a domain.  
2. App generates a **new domain‑oriented question** (ensures variety, avoids repeats).  
3. User submits an answer or clicks **“New question”** to skip.  
4. System returns structured feedback; history is shown and saved.  
5. Click **“New session”** to restart with a fresh session id.

### Architecture
```
src/ai_interview_bot/
  backend/
    llm_providers.py   # Ollama HTTP client with /api/chat -> /api/generate fallback
    prompts.py         # interviewer, generator, metadata, evaluator prompts (escaped JSON)
    generator.py       # LLM-only question generator + metadata extractor (tags/difficulty)
    evaluator.py       # Strict JSON evaluation + auto-repair when malformed
  cli/
    run.py             # terminal loop; diversity, de-dup, logging
  web/
    app.py             # FastAPI routes (index/start/chat/answer/new)
    templates/         # Jinja + Tailwind + HTMX views (index.html, chat.html)
  configs/
    domains.yaml       # domain -> persona
storage/
  sessions/            # CLI session logs
  web_sessions/        # Web session logs
  asked_index.json     # global normalized questions for repeat-avoidance
```

### Tech Stack
- **Python 3.10+**, **Poetry**, **pytest**  
- **Ollama** (local LLM; default `llama3.1:8b`, configurable)  
- **FastAPI + Jinja + HTMX + Tailwind** (no bundler)  
- **GitLab CI** (Poetry install + tests)

## 5) Data & Privacy

- **No external datasets** required; **questions generated by LLM**.  
- **Session logs** are JSON on local disk only (no PII beyond user-typed text).  
- Users may delete `storage/` to remove history.  
- Ethical guardrails: prompts ask for professional, non-discriminatory questions.

---

## 6) Prompting & Evaluation

- **Question Generation:** domain persona + recent context + **avoid list** + **avoid topics** + difficulty hint.  
- **Near-duplicate detection:** Jaccard similarity over normalized tokens.  
- **Metadata Extraction:** LLM returns `{"tags": [...], "difficulty": ...}` for diversity accounting.  
- **Evaluation:** LLM returns JSON with five rubric scores (1–5), summary, three tips, and an ideal answer.  
- **Robustness:** if JSON parsing fails, the system asks the LLM to **repair to valid JSON** and retries.

## 8) How to Run

### Web UI
```bash
poetry install
export AI_BOT_MODEL="llama3.1:8b"   # or any local Ollama model you have
poetry run ai-bot-web
# open http://127.0.0.1:8000
```

### CLI
```bash
poetry run ai-bot
```

Outputs:
- Web sessions → `storage/web_sessions/`  
- CLI sessions → `storage/sessions/`  
- Global no-repeat index → `storage/asked_index.json`

## 9) Risks & Mitigations

- **Model variability / JSON instability** → strict prompts + repair step; graceful skip on failure.  
- **Repeat questions** → global index + diversity rotation + near-duplicate detection.  
- **Performance on small models** → configurable model/temperature/context; keep-alive for warm weights.  
- **Scope creep** → clear MVP; phase future features.
